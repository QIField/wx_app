关键实现：四步链路

全部在 ChatComposer.vue 现有结构内完成，零新增依赖。

1

拦截 paste

现有 onPaste 里先扫 e.clipboardData.items，找到 type.startsWith('image/') 的项。找到才 preventDefault()，找不到维持纯文本逻辑不变。

2

提取 File

item.getAsFile() 拿到真实 File 对象（含 MIME），QQ/微信截图、系统截图工具、网页复制图片统统覆盖。

3

复用 sendFile

直接调 chat.sendFile(file) —— 大小校验、MIME→msg_type=2 分发、payload 组装全在 store 里现成，组件只管喂文件。

4

气泡反馈

上传中显示转圈+百分比气泡，完成后就地替换为图片气泡（本地 blob 先展示，毫秒级感知）。

落地 Diff（ChatComposer.vue）

实际改动只涉及 onPaste 一处 + 一个发送中提示，其余全部复用。

frontend/src/components/ChatComposer.vue

/* 粘贴分发：图片 → 直接 sendFile（微信同款）；其余 → 维持纯文本插入 */ function onPaste(e) { // ① 优先找剪贴板里的图片（QQ/微信截图、系统截图、网页复制图片都走这） e.preventDefault() const text = e.clipboardData?.getData('text/plain') || '' if (text) { insertPlainTextAtCursor(composerEl.value, text) refreshDraft() } const items = e.clipboardData?.items || [] const imgItem = [...items].find((it) => it.type.startsWith('image/')) if (imgItem && chat.currentId) { e.preventDefault() // 图片不进编辑器，直接走文件上行 const file = imgItem.getAsFile() if (file) chat.sendFile(file).catch((err) => ElMessage.error(err.message)) return } // ② 无图片：维持原有「仅收纯文本」逻辑，防富文本破坏编辑器结构 e.preventDefault() const text = e.clipboardData?.getData('text/plain') || '' if (text) { insertPlainTextAtCursor(composerEl.value, text) refreshDraft() } }

上传中转圈气泡由 chat store 的 sendFile 现有 _afterSend 流程承接；若想增强，可在 MessageRow 对 status==='sending' 的图片消息加转圈样式（本次改动非必需）。

边界情况

图文混合剪贴板

Office 复制常同时带 text/plain 和 image。策略：图片优先（微信同款），文本忽略；从 Excel 复制单元格得到的是纯文本，不受影响。

多图粘贴

循环处理所有 image 项，逐张调 sendFile 并发上行；演示中也能触发（浏览器一般只带一张）。

超大文件

不新增校验——sendFile 已有 UPLOAD_MAX_BYTES(50MB) 上限，超限直接 ElMessage 报错，链路天然闭环。

未选中会话

chat.currentId 为空时不消费 paste，图片项落到「纯文本回退」（大多数场景无剪贴板文本，等于无操作，与现状一致）。

Linux/Wayland 截图工具

部分截图工具把图片放 clipboard 而非 clipboardData，浏览器拿不到——微信桌面同样有此问题，不在本次范围，保持现状。

与 @提及/表情不冲突

图片直接上行，不进 contenteditable，serializeComposer 与 collectMentionIds 逻辑零改动。
