匿WX 工作台 · 原型 wxid 全链路脱敏方案
方案说明 效果演示

wxid 不出后端：出参脱敏 + ID 通信 + 匿名展示

核心思路：前端看不到的东西才是真的看不到。只靠前端替换显示藏不住 wxid （F12 的 Network 面板一览无余），所以脱敏必须做在后端出参层： 所有 API / WebSocket 响应不再携带 wxid，前端与后端的通信改用业务 ID（会话号 / 联系人行号）； 未获取到名称的用户以「匿名 + 编码」代称（如 匿名 U7F3K2，同码同人、跨屏可分辨）+ 匿名头像。

泄漏点（现状） 改造点（新增/修改） 保持不变

1现状：wxid 到达前端的 6 条路径

逐文件核对后端出参与前端渲染，全部需要在本次改造中封死。

#路径位置泄漏形态
1会话列表 / 消息接口的 conversation 对象backend/api/conversations.py · _conv_json响应字段 wxid；前端 name || wxid 兜底
2消息对象backend/api/conversations.py · _msg_json响应字段 sender_wxid；群成员无昵称时 sender_name 回退为 wxid 原文（库内存的就是 wxid）
3通讯录列表backend/api/contacts.py · _item_json响应字段 wxid；名字兜底 name or wxid
4WebSocket 实时推送backend/sync/message_sync.py · broadcast_messagessender_name 无昵称时回退 wxid 原文
5设备卡片 / 顶栏账号切换backend/models/user_device.py · to_json无备注时 display_name 回退 openid（即设备微信号）
6前端直接渲染frontend: ContactsPanel / ContactDetail / ConvList / ChatPanel / MessageRow / stores「微信号：wxid_…」、通讯录第二行直接显示 wxid、搜索框按 wxid 命中、头像取 wxid 首字母

2脱敏数据流（改造后）

wxid 只存在于数据库与后端内部逻辑；出参层是唯一出口，输出的是 ID + 匿名别名 + 已解析名称。

3出参契约对照（Before → After）

以会话/消息/通讯录三类核心响应为例；红行为删除字段，绿行为新增/变更。

  "conversation_id": 1024,
- "wxid": "wxid_l2k9f8a733",     // ✕ 删除
  "chat_type": 1,
  "name": null,                    // 未解析 → null
  "avatar": null,
+ "alias": "U7F3K2",

规则 名称：contact.name / 群成员 nickname 缺失、或仍是 wxid 原文时 → 出参 name=null，前端统一拼显示名「匿名 + alias 编码」（如 匿名 U7F3K2）——同码同人、不同人编码互异，多未命名成员一眼可分。 头像：仅名称已解析的用户下发真实 avatar；未解析用户 avatar=null，前端画「人形图标 + 稳定色相」匿名头像（同一人颜色恒定，不同人不同色，群聊可区分）。 alias：HMAC-SHA256(wxid, 服务端密钥) 截断 6 位，不可逆、跨会话稳定；既是未命名用户的显示名，也是所有联系人的展示标识，不参与任何写接口。

4接口签名变更（通信不再用 wxid）

接口现状改造后
发起会话
POST /api/conversations		 body 带 wxid body 改为 { contact_id, chat_type }；后端按 contact 行反查 wxid 再建会话
联系人档案
GET/PUT /api/contacts/<wxid>/profile		 路径参数是 wxid 改为 /api/contacts/<contact_id>/profile；ContactProfile 内部仍按 wxid 存取（不动表结构）
WebSocket new_message
backend/sync/message_sync.py		 sender_name 回退 wxid 原文 复用同一脱敏函数：昵称缺失 → 「匿名 + 编码」，sender_wxid 不下发
设备卡片
GET /api/devices		 display_name 无备注回退 openid 回退改为「设备1 / 设备2 …」（按绑定顺序）；工作台不再出现 openid 字样
搜索匹配
前端 stores/contacts.js、ConvList.vue		 关键词命中 wxid 仅匹配 名称 / 备注（wxid 已不可见，自然不再参与匹配）

5匿名展示规则（前端三件套）

要素规则实现
名称 name 为 null / 空 → 显示「匿名 + 编码」（匿名 U7F3K2）；群消息发言人同理，不同成员编码互异、天然可分辨 统一收敛到 displayNameOf(item) 工具函数，替换现有 5 处 name || wxid 兜底
头像 未解析用户：灰色系人形图标，色相 = hash(alias) 决定，同人恒定；已解析但无图：沿用名字首字色块 新增 AnonAvatar.vue（或 utils 内 hsl 计算）；群聊中多个未命名成员颜色互异、可区分
匿名标识 联系人详情「微信号：wxid」一行改为「匿名标识：U7F3K2」；通讯录第二行 wxid 预览改显示 匿名标识（已命名）/「资料未同步」提示（未命名） alias 由后端下发，前端零计算（避免前端拿到 wxid 才能算哈希）
边界 消息正文 / last_msg 里若被人贴了 wxid 文本，属于聊天内容本身，不做正则脱敏（会破坏业务语义），方案不覆盖；管理端「账号管理-设备绑定」仍需输入 openid 才能绑定设备，见决策点。

6需要拍板的决策点

编号问题方案建议
D1管理端（developer/admin 角色）的账号管理页是否也隐藏 openid？建议保留：绑定设备必须录入 openid，且仅管理角色可见；工作台普通用户全量脱敏
D2未命名用户是否允许看真实头像？本方案按「名称未解析 → 头像一并匿名」处理（名称和头像来源于同一批资料收割，未解析通常意味着头像同样缺失）
D3alias 是否需要参与搜索？默认不参与（alias 是展示辅助，不是身份）；如运营需要按匿名标识找人，可后补后端参数
