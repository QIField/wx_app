# 自动报价实施方案（业务端落地）

> 2026-11-17 定稿。配套：接口契约 [quick-quote-api.md](quick-quote-api.md)、交互原型 `prototypes/quick-quote-panel/`。
> 节奏：每阶段测试通过才进下一步；阶段 0-2 一次交付，3-4 一次，5-6 一次；每阶段独立 feat 提交。

## 0. 产品决议汇总（已定案，不再讨论）

| 事项 | 决议 |
|---|---|
| 触发 | 开启自动报价者：新消息后静默 3s（新消息重置计时）→ 拉最近 10 条（含客服自己发的）→ 一次 AI 分析 |
| 防重 | 无状态，AI 靠窗口内上下文判断；闸门：`quoted=false` 才自动发，quoted=true / 字段缺失 → 人工 |
| 图片回溯 | V1 不做（窗口固定 10 条）；漏识别场景出现后再加「按发送者查最近一张图」增强 |
| 黑名单 | V1 只做配件黑名单（不做客户黑名单） |
| 报价开关 | 存通讯录备注模块；**群开启优先于用户开启**（群会话只看群开关，单聊看用户开关） |
| 普通模式 | 面板 AI 开关关闭 = 纯手动：不分析新消息，手动查询/比价/历史不受影响 |
| 发送 | 我方业务端记来源会话，报价完调自家发消息接口；**产品图在前 + 话术在后，分开发，默认发** |
| 选购链接 | 只做按钮占位，等 CRM 商城 URL 规则后补 |
| 价格 | 我方价 × 客户等级系数（contact_profile 扩展 level，默认普通客户 0.90） |
| 改价 | 预览/待人工卡支持发送前手动改价（价格行 ✎ 按钮），话术与省比联动，发送记录 price_json 存改后价 |

## 2. 契约 B：询价状态机（quote_inquiry.status）

```
                 ┌────────── AI 场景分流 ──────────┐
   AI 返回场景 ──┤ 配件黑名单命中 ──→ blocked(拦截，终态)
                 │ quoted=true / 字段缺失 ──→ review(待人工)
                 │ quoted=false 且完整 ──→ pending(待报价)
                 │
   pending ──报价编排成功──→ 已生成报价卡，等待发送
   发送成功 ──→ sent(已报价，终态)
   发送失败 ──→ review(带失败标记，可重试 / 可忽略)
   review ──人工确认发送──→ sent；──忽略──→ ignored(终态)
```

| 状态 | 值 | 进入条件 | 出口 |
|---|---|---|---|
| pending | 0 | quoted=false 且字段完整且未命中黑名单 | → sent / review |
| review | 1 | quoted=true / 缺 vin 且缺配件名 / 发送失败 | → sent / ignored |
| blocked | 2 | 配件命中黑名单 | 终态 |
| sent | 3 | 发送成功（图+话术） | 终态 |
| ignored | 4 | 人工忽略 | 终态 |

表结构最小集：`id, conversation_id, sender_name, vin, part_name, quoted, status, raw_time, price_json, created_at`。

## 3. 契约 C：开关真值表（source of truth）

两级开关，**AND 关系**：

- **通讯录开关（资格闸门，业务端 DB）**：contact_profile.auto_quote，群/用户各一；群会话只看群开关，单聊看用户开关
- **面板执行开关（业务端 user_config，跟随登录账号跨端一致）**：AI 开关 + 自动报价模式（仅预览/自动发送）

| 通讯录开关(资格) | 面板 AI 开关(执行) | 模式 | 行为 |
|---|---|---|---|
| 开 | 开 | 自动发送 | 全自动：quoted=false 直接发送 |
| 开 | 开 | 仅预览 | AI 分析入列，不自动出价 |
| 开 | 关 | — | 普通模式：不分析新消息，纯手动 |
| 关 | 任意 | 任意 | 完全不进入流程（用户开关对群会话无效） |

## 4. 契约 D：失败态 UI（阶段 5 前端行为）

- 发送失败的卡片：红左边条（`.failed`）+「✕ 发送失败」badge + 按钮变「重试发送」，状态回 review
- 重试成功 → 绿 badge「✓ 已发送至会话」，红条消失
- 原型已实现（`sendFail` 场景演示），前端接入时按此还原

## 5. 分阶段实施（每阶段测试通过才进下一步）

### 阶段 0：开关与配置存储
1. contact_profile 加 `auto_quote`（0/1）、`level`（客户等级）；profile 接口支持读写
2. 新建配置存储：配件黑名单列表增删查；面板执行开关/模式（user_config）

**测试**：接口手工调，开关/黑名单/等级持久化重启不丢。
**提交**：`feat: 通讯录自动报价开关、客户等级与配件黑名单存储`

### 阶段 1：快捷报价客户端
1. 新建 `backend/qq_client.py`：11 端点封装（基址/openid 进 .env，测试与生产分开），统一 POST form、超时 90s、401/500/非 JSON 兜底
2. 单测：form 组装、错误兜底（500 Flask HTML 不崩）

**测试**：pytest 全绿 + 真实链路两条已知参数（VIN WBAWX3100G0L69597、OE 1665000075）。
**提交**：`feat: 快捷报价服务客户端与单测`

### 阶段 2：AI 分析触发器（核心，完成后暂停验收）
1. 新建 `backend/auto_quote.py` 挂消息同步钩子：按契约 C 判资格 → 每会话 3s 去抖 → 拉最近 10 条（含客服）→ 组装 chat_content（文本 `时间【昵称】：内容`；图片公网 URL + 备注条目；不做历史回溯）→ 调 extract_parts_demand → 按契约 B 落表
2. 单测重点（防切割）：组装格式逐字段断言、去抖合并、图片备注、多发送者场景

**测试**：单测全绿；测试群连发「图→文字」5 条只触发 1 次分析且内容完整；闲聊返回 0 场景不落表。
**过测标准**：提取质量人工抽查 ≥90% 正确再进阶段 3。
**提交**：`feat: 自动报价触发器（去抖+上下文组装+AI分析）`

### 阶段 3：守门分发
按契约 B 状态机分流四种场景；提供 `GET /api/quote/inquiries?status=` 给前端。

**测试**：mock 服务方返回四种场景（正常/quoted=true/缺字段/黑名单），断言状态全部分流正确。
**提交**：`feat: 询价守门分发与人工队列`

### 阶段 4：报价计算链
编排：有 vin 走 vininfo，名称走 partno → OE → product_list → × 等级系数 → 话术模板（含 OE）。**过测标准：产出契约 A 的 r 结构，前端可原样渲染。**

**测试**：三条真实链路（OE 1665000075 / VIN WBAWX3100G0L69597 / 名称「节温器」）各出一张价，字段完整、价格与手工调用一致。
**提交**：`feat: 报价计算编排（译码→OE→产品价→系数）`

### 阶段 5：自动发送
1. 调自家 `POST /api/conversations/{id}/messages`：产品图 msg_type 2 在前 + 话术 msg_type 1 在后
2. 图片经 `/media/uploads/` 转存得公网 URL（来源见前置确认①）
3. 失败按契约 D 回 review 可重试

**测试**：测试号真实收发「图→文」两条；黑名单拦截验证；断网验证失败态回滚不丢失。
**提交**：`feat: 自动报价发送（产品图+话术）`

### 阶段 6：前端接入 + 上线观察
1. InfoPanel.vue 按原型改造：自动预览流 + 待处理/已报价/已购 + 设置页
2. 全流程联调：契约 C 真值表 8 种组合逐一过
3. 上线监控三指标：重复报价次数 / AI 调用失败率 / 自动发送成功率

**提交**：`feat: 报价处理台前端接入`
